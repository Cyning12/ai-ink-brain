## 二、后端 `ai-ink-brain-api-python`：无权限 Text2SQL 与文档归档（`2c52e75`）

### 2.1 问题与目标

旧行为在 **表级策略 / RLS / 预取失败** 等场景下，仍可能 **先 RAG 再绕回 Text2SQL**，终态易被泛化文案掩盖。目标为：**稳定错误码 + 用户可读中文无权限说明**、**拒绝后不再调用 `rag_search`**、**终态与 SSE 模拟总结流一致**。

### 2.2 实现要点

- **`api/agent.py`**：`FailureTypeHandler` 对 **`SQL_EXEC_PERMISSION_DENIED` / `CHATBI_SQL_DENIED` / `CHATBI_SQL_WRITE_DENIED`** 走 **`direct_answer` + `stop_now`**，与常量 **`TEXT2SQL_DENY_FINAL_ANSWER_CODES`** 对齐；移除依赖 **`suppress_sql_fallback` / `last_text2sql_denial_message`** 的旧绕路。无权限时 **`success=False`** 仍须在 **`next_action == "final_answer"`** 等条件下发射与 **`assistant.message`** 一致的 **模拟 `text2sql_summary` LLM 流**（修复「仅有 `tool.call.end` 的 error、无 `agent.llm` 流」的回归）。
- **`api/tools.py`**：策略预取失败映射 **`CHATBI_SQL_WRITE_DENIED`**、RLS 等用户面向文案；与预取元数据字段配合（与后续 `ce1b939` 中的 schema 阶段衔接）。
- **`tests/test_unified_chat_backend_v2_agent.py`**：新增 **`test_v2_text2sql_write_denied_stops_without_rag`**，断言 **`rag_search` 不得被调用**。

## 三、后端 `ai-ink-brain-api-python`：Schema 预取、统一路径与契约门禁（`ce1b939` 及同日早段）

### 3.1 Schema 预取任务（`task_text2sql_schema_prefetch_before_mutate_v1`）

- **动机**：检索 DDL 未覆盖目标表或列证据不足时，模型仍可能 **臆造 INSERT/UPDATE 列名**，执行期在 Postgres 报错。
- **完成态**：在 **`llm_generate_sql` 之前** 增加 **只读元数据预取**（`information_schema` 等受限模板），结果注入 **`build_sql_prompt`**；与 **`filter_text2sql_retrieved`、ChatBI 表策略** 可见表集合对齐；失败时 **结构化拒绝**（当 `schema_prefetch_source=error_policy` 时含 **`CHATBI_SQL_WRITE_DENIED`**）。
- **主要文件**：`api/text2sql_schema_prefetch.py`（新）、`api/text2sql_core.py`、`api/tools.py::text2sql_execute`、`api/unified_chat.py`、**`tests/test_text2sql_schema_prefetch.py`**、种子与说明 SQL（`docs/text2sql/v1/sql/` 下 **`agent_info_postgres_upsert_prereq.sql`**、**`agentinfo.sql`**、**`chatbi_03_seed_table_policy_demo.sql`** 等）、**`docs/_tech_graph/11_flow_text2sql.md` / `.ai.md`**、**`docs/meta/PROJECT_CONFIG_AI_INK_BRAIN_API_PYTHON.md`**（env 说明回填）。
- **可观测**：**`text2sql.phase.start/end`** 中 **`schema_prefetch`** 阶段；JSON 日志 **`text2sql_phase_end`** 可带 **`schema_prefetch_source` / `schema_prefetch_tables`**（与 SSE payload 扩展一致）。

### 3.2 `tech_graph_contract_check` 与 `text2sql.phase.end` 静态真值

静态门禁脚本对 **`_t2sql_chain_dict("text2sql.phase.end", …)`** 的解析采用「类型字符串之后片段中 **首个 `{`**」启发式。若第四参为 **变量名** `payload`，首个 `{` 会误匹配到下方 **`chain_pf = { "schema_prefetch_source": …`**，导致 **MISSING `latency_ms`/`phase_id`/`subphase_id`** 与 **EXTRA `schema_prefetch_*`**。修复方式：在 **`_emit_phase_end`** 内对 **`text2sql.phase.end`** 传入 **字面量 dict**（含 **`**(chain_extra or {})`**），使扫描锚点与运行时 payload 一致；**`_contract_manifest.json` 的必填三键不变**（spread 键不进入静态最小集，避免假 MISSING）。
